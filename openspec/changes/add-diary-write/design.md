# Design

## Context

저장소에는 OpenSpec 설정만 있고 앱 코드·빌드 도구·`package.json`이 없다. 목표는 서버 없이 브라우저에서 바로 여는 정적 페이지다. 동기는 proposal.md의 Why, 동작 요구사항은 `specs/diary-entries/spec.md`를 따른다.

## Goals / Non-Goals

**Goals:**
- `index.html`을 브라우저로 열기만 하면 동작한다 (빌드·서버 불필요).
- 다음 변경(수정·삭제)이 붙기 쉽도록 기록마다 고유 id를 둔다.

**Non-Goals:**
- 오프라인 동작 보장 (Tailwind를 CDN으로 받기 때문)
- 자동 테스트 환경 구축 — 이번에는 수동 확인 시나리오로 검증한다.

## Decisions

### 1. 파일 구성: `index.html` + `app.js` 두 개
- 마크업은 `index.html`, 동작은 `app.js`(`<script src="app.js" defer>`)로 나눈다.
- 대안: 한 파일에 인라인 스크립트 → 작지만 다음 변경 때 diff 보기가 불편하다.
- ES 모듈(`type="module"`)은 쓰지 않는다. `file://`로 열면 모듈 로딩이 CORS로 막히기 때문이다.

### 2. 스타일: Tailwind Play CDN
- `<script src="https://cdn.tailwindcss.com"></script>`로 빌드 없이 유틸리티 클래스를 쓴다.
- 대안: Tailwind CLI 빌드 → 운영 품질이지만 Node 빌드 단계가 생겨 "Vanilla, 빌드 없음" 구성과 어긋난다. 배포할 때 CLI로 바꾸는 것은 별도 변경으로 둔다.

### 3. 저장 형식: `localStorage` 키 하나에 JSON 배열
- 키: `diary.entries`
- 값: 저장 순서대로 쌓인 배열
  ```json
  [{ "id": "1767157500000-ab12", "date": "2026-12-31", "time": "14:05", "text": "산책을 했다", "createdAt": 1767157500000 }]
  ```
- `date`, `time`은 화면 표시용으로 저장 시점에 로컬 시간 기준으로 계산해 고정한다. 나중에 기기 시간대가 바뀌어도 쓴 당시의 날짜·시간이 유지된다.
- `createdAt`(epoch ms)은 정렬용이다. 같은 분에 쓴 기록도 순서가 갈린다. 같은 ms에 대비해 정렬은 `createdAt` 내림차순, 같으면 배열에서 뒤에 있는 것이 먼저다.
- `id`는 `crypto.randomUUID()`를 쓰되, `file://` 등 지원되지 않는 환경을 위해 `createdAt`과 난수 조합으로 대신한다.
- 대안: 날짜별 객체 `{ "2026-12-31": [...] }` → 날짜 묶음 보기에 유리하지만 이번 범위는 단순 최신순 목록이라 배열이 더 단순하다.

### 4. 날짜·시간 계산은 로컬 시간 기준
- `getFullYear()/getMonth()/getDate()/getHours()/getMinutes()`로 직접 조립하고 두 자리로 맞춘다.
- `toISOString()`은 UTC라서 한국에서 오전 9시 전에 쓰면 전날 날짜가 된다. 쓰지 않는다.
- 화면의 오늘 날짜는 페이지를 열 때 한 번 계산한다. 자정을 넘겨 페이지를 열어 둔 경우의 갱신은 다루지 않는다 (아래 Risks).

### 5. 렌더링: 저장 후 목록 전체 다시 그리기
- 기록 수가 적으므로 저장할 때마다 목록을 통째로 다시 그린다.
- 사용자 입력은 `textContent`로 넣는다. `innerHTML`을 쓰지 않아 입력한 HTML이 실행되지 않는다.

### 6. 목록 스크롤: 고정 최대 높이 + `overflow-y-auto`
- 목록 항목 높이를 한 줄로 고정(`truncate` 또는 줄바꿈 허용 시 최소 높이)하고, 목록 컨테이너에 5개 높이만큼 `max-height`를 준다.
- 100자 기록이 좁은 화면에서 여러 줄이 되면 "5개 높이"가 어긋나므로, 항목은 한 줄 + 말줄임(`truncate`)으로 표시하고 전체 내용은 `title` 속성으로 보여준다.

### 7. 빈칸 경고: 입력칸 아래 인라인 문구
- 입력칸 바로 아래에 평소엔 숨겨진 경고 문구 요소(`role="alert"`, 빨간 글씨)를 두고, 빈 값으로 저장을 시도하면 보이게 한 뒤 입력칸에 포커스를 준다.
- `input` 이벤트나 저장 성공 시 다시 숨긴다.
- 대안: `alert()` → 구현은 가장 쉽지만 Enter로 저장하는 흐름을 끊고, 대화상자를 닫는 데 다시 Enter가 필요해 한 줄 입력과 어울리지 않는다.
- 문구 요소 자리를 미리 확보(`min-height` 또는 `invisible` 토글)해 경고가 뜰 때 목록이 아래로 밀리지 않게 한다.

### 8. 저장 실패·손상 데이터 처리
- 읽기: `JSON.parse` 실패나 배열이 아닌 값이면 빈 배열로 시작한다 (원본 값은 덮어쓰기 전까지 남는다).
- 쓰기: `localStorage` 접근이 막히거나(사생활 보호 모드 등) 용량 초과로 예외가 나면 `alert`로 저장 실패를 알리고 입력 내용은 지우지 않는다.

## Risks / Trade-offs

- [Tailwind Play CDN은 개발용이며 인터넷이 없으면 스타일이 빠진다] → 기능은 동작한다. 배포 시점에 CLI 빌드로 바꾸는 변경을 따로 만든다.
- [기록이 브라우저에만 있어 사이트 데이터를 지우면 사라진다] → 이번 범위에서는 받아들인다. 내보내기는 이후 변경 후보.
- [손상된 데이터를 빈 배열로 시작한 뒤 새로 저장하면 원본이 덮어써진다] → 손상 자체가 드물고, 덮어쓰기 전 원본을 `diary.entries.corrupt` 키에 한 번 백업한다.
- [페이지를 연 채로 자정을 넘기면 상단 날짜가 어제로 남는다] → 기록 자체의 날짜는 저장 시점에 계산하므로 맞다. 상단 표시 갱신은 필요해지면 다음 변경에서 다룬다.
- [`file://`로 열 때 `localStorage`가 브라우저마다 다르게 동작할 수 있다] → 주요 확인은 로컬 정적 서버(예: VS Code Live Server)로 한다.
