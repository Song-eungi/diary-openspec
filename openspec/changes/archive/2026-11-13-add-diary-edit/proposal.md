# Proposal

## Why

지금은 한 번 저장한 기록을 고칠 방법이 없어, 오타 하나만 있어도 그대로 남거나 새로 써야 한다. 첫 변경(`add-diary-write`)에서 기록마다 고유 `id`를 두었으므로 이를 기준으로 수정 기능을 더한다.

## What Changes

- 목록의 각 기록에 [수정] 버튼을 둔다. 지난 기록을 포함해 모든 기록을 수정할 수 있다.
- [수정]을 누르면 그 항목이 목록 안에서 바로 입력칸 + [저장]·[취소]로 바뀐다 (인라인 편집). 한 번에 하나만 편집한다.
- Enter 또는 [저장]으로 수정을 저장하고, Esc 또는 [취소]로 원래 내용으로 되돌린다.
- 수정해도 처음 작성한 날짜·시간과 목록 순서는 바뀌지 않는다. 내용이 실제로 바뀐 기록에는 "수정됨" 표시가 붙고, 수정 시각이 함께 저장된다.
- 편집 입력에도 작성과 같은 규칙을 적용한다: 앞뒤 공백 제거, 최대 100자, 빈칸이면 저장하지 않고 경고, 한글 조합 중 Enter 무시.
- 상단의 새 기록 입력은 편집과 독립적으로 그대로 동작한다.

범위 밖:
- 기록 삭제
- 수정 이력(이전 내용) 보관·되돌리기
- 날짜·시간 직접 변경

## Capabilities

### New Capabilities
- 없음

### Modified Capabilities
- `diary-entries`: 저장된 기록을 목록에서 수정하는 요구사항 추가 (기존 작성·목록 요구사항은 그대로)

## Impact

- 수정 파일: `app.js` (편집 상태·렌더링·저장), `index.html` (필요 시 마크업), `README.md` (기능·데이터 설명)
- 데이터: 기록 객체에 선택 필드 `updatedAt`(epoch ms) 추가. 기존 기록은 그대로 읽히며 변환 작업이 필요 없다.
- 외부 의존성 변화 없음
