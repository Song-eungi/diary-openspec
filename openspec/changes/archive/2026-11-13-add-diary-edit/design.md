# Design

## Context

`app.js`는 전역 `entries` 배열을 들고, 저장할 때마다 `renderList()`가 `listEl.replaceChildren()`으로 목록 전체를 다시 그린다. 항목은 `h-12` 고정 높이, 목록은 5개 높이 `max-height` + `overflow-y-auto`다. 기록마다 `id`가 있다. 동기와 범위는 proposal.md, 동작은 `specs/diary-entries/spec.md`를 따른다.

## Goals / Non-Goals

**Goals:**
- 기존 렌더링 구조(전체 다시 그리기)를 유지하면서 인라인 편집을 얹는다.
- 다시 그려도 스크롤 위치와 편집 중인 입력 내용이 사라지지 않게 한다.

**Non-Goals:**
- 삭제, 수정 이력 — proposal의 범위 밖
- 목록 부분 갱신(diff 렌더링) 최적화 — 기록 수가 적어 불필요

## Decisions

### 1. 편집 상태: 모듈 변수 `editingId` 하나
- `let editingId = null`. `renderList()`가 각 기록을 그릴 때 `entry.id === editingId`면 편집 행, 아니면 일반 행을 만든다.
- 한 번에 하나만 편집한다는 요구가 자료구조로 보장된다. 다른 항목의 [수정]을 누르면 `editingId`만 바꾸고 다시 그리므로 이전 편집은 자연히 버려진다.
- 대안: DOM에서 해당 `<li>`만 교체 → 다시 그리기가 일어나는 다른 경로(새 기록 저장)와 상태가 어긋나기 쉽다.

### 2. 버튼 이벤트: 목록에 위임
- 행 버튼에 `data-action="edit|cancel"`과 `data-id`를 달고 `listEl`의 `click` 하나로 처리한다. 다시 그릴 때마다 리스너를 붙였다 뗄 필요가 없다.

### 3. 편집 행: 행 안의 `<form>`
- 편집 행은 `<li>` 안에 `<form>`(입력칸 `maxlength="100"` + [저장] submit + [취소] button)을 둔다. Enter·[저장] 모두 `submit`으로 들어와 기존 작성 폼과 같은 방식이 된다.
- 날짜·시간 표시는 편집 중에도 왼쪽에 그대로 둔다 (어떤 기록을 고치는지 보이게).
- 행 높이는 `h-12` 그대로, 입력칸·버튼은 `h-8` + `text-sm`으로 맞춘다 → 5개 높이 스크롤 유지.
- `keydown`: 한글 조합 중(`isComposing` 또는 `keyCode 229`) Enter·Esc는 무시, 그 외 Esc는 취소.
- 편집 시작 시 입력칸에 포커스하고 커서를 끝으로 둔다. 저장·취소 후에는 그 행의 [수정] 버튼에 포커스를 돌려준다(키보드 사용자용).

### 4. 편집 행의 빈칸 경고: 행 안에서 표시
- 상단처럼 입력칸 아래 문구를 두면 행 높이가 늘어 스크롤 요구를 깨뜨린다.
- 대신 입력칸에 빨간 테두리(`ring-red-400`)를 주고, 비워진 입력칸의 placeholder를 "내용을 입력해 주세요."(빨간색)로 보여준다. 화면 읽기 도구용으로 같은 문구를 담은 `role="alert"` `sr-only` 요소를 행 안에 둔다.
- 입력이 생기면(`input`) 테두리·alert를 지운다. placeholder는 글자가 있으면 원래 안 보인다.
- 대안: `title` 툴팁 → 마우스 없이 보이지 않는다.

### 5. 저장 규칙
- 새 값 = 입력값 `trim()`. 비어 있으면 4번 경고 후 편집 유지.
- 새 값이 기존 `text`와 같으면 아무것도 저장하지 않고 편집만 닫는다 → "수정됨"이 붙지 않는다.
- 다르면 `text`와 `updatedAt = Date.now()`를 바꾼 **새 배열**을 만들어 `saveEntries()`. 실패하면 기존과 같은 `alert`를 띄우고 편집 상태와 입력 내용을 유지(메모리의 `entries`도 바꾸지 않음).
- `date`, `time`, `createdAt`, 배열 내 위치는 건드리지 않으므로 정렬·표시가 그대로다.

### 6. 데이터: 선택 필드 `updatedAt`
- `updatedAt`(epoch ms)이 있으면 수정된 기록. 없으면 원본. 기존 저장 데이터는 변환 없이 그대로 읽힌다.
- 대안: `edited: true` 불리언 → 수정 시각을 함께 보여줄 수 없다.

### 7. "수정됨" 표시
- 일반 행에서 내용(`truncate`) 오른쪽에 `shrink-0` 작은 회색 글씨 "수정됨"을 둔다. 긴 내용이 잘려도 표시는 항상 보인다.
- `title`에 `수정: YYYY-MM-DD HH:mm`(로컬 시간, 기존 `formatDate`/`formatTime` 재사용)을 넣어 마우스를 올리면 수정 시각이 보인다.

### 8. 다시 그릴 때 스크롤·편집 내용 보존
- `replaceChildren()`은 목록을 잠깐 비워 `scrollTop`이 0으로 돌아간다. 아래쪽 기록을 수정하면 목록이 맨 위로 튄다. → `renderList()` 시작에 `scrollTop`을 저장하고 끝에서 되돌린다.
- 편집 중에 상단에서 새 기록을 저장하면 목록이 다시 그려진다. 이때 편집 입력칸의 현재 값을 읽어 두었다가 새 편집 행에 다시 채운다 → 편집 중이던 내용이 사라지지 않는다.

## Risks / Trade-offs

- [좁은 화면에서 날짜·시간 + 입력칸 + 버튼 2개가 한 줄에 빠듯하다] → 입력칸은 `min-w-0 flex-1`로 줄어들게 하고 버튼 글씨를 짧게(저장/취소) 유지. 360px 폭에서 확인한다.
- [placeholder 경고는 입력칸이 비어 있을 때만 보인다] → 경고가 뜨는 조건 자체가 "비어 있음"이므로 맞는다. 공백만 있을 때는 저장 시 입력칸을 비우고 경고를 띄운다.
- [다른 항목 [수정]을 누르면 편집 중이던 내용이 확인 없이 버려진다] → 사용자가 결정한 동작이며, 한 줄이라 잃는 양이 작다.
