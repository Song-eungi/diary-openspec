# diary-entries Specification

## Purpose

사용자가 하루를 한 줄로 기록하고, 저장된 기록을 최신순으로 다시 볼 수 있게 한다. 기록은 사용자의 브라우저 안에만 보관된다.

## Requirements

### Requirement: 오늘 날짜 표시
시스템은 화면을 열었을 때 사용자 기기의 로컬 시간 기준 오늘 날짜를 `YYYY-MM-DD` 형식으로 표시 SHALL 한다.

#### Scenario: 화면을 열면 오늘 날짜가 보인다
- **GIVEN** 사용자 기기의 로컬 날짜가 2026년 12월 31일이다
- **WHEN** 사용자가 다이어리 화면을 연다
- **THEN** 화면 상단에 `2026-12-31`이 표시된다

#### Scenario: UTC와 날짜가 다른 시간대
- **GIVEN** 사용자 기기의 시간대가 UTC+9이고 로컬 시각이 2026-12-31 08:30이다 (UTC로는 2026-12-30)
- **WHEN** 사용자가 다이어리 화면을 연다
- **THEN** `2026-12-31`이 표시된다

#### Scenario: 한 자리 월·일
- **GIVEN** 사용자 기기의 로컬 날짜가 2027년 1월 5일이다
- **WHEN** 사용자가 다이어리 화면을 연다
- **THEN** `2027-01-05`처럼 월과 일이 두 자리로 표시된다

### Requirement: 한 줄 기록 저장
시스템은 사용자가 입력한 한 줄을 저장 버튼 클릭 또는 Enter 키로 저장 SHALL 하며, 각 기록에 저장 시점의 로컬 날짜(`YYYY-MM-DD`)와 시간(`HH:mm`, 24시간제)을 함께 남겨야 MUST 한다. 저장 후 입력칸은 비워진다.

#### Scenario: 버튼으로 저장
- **GIVEN** 로컬 시각이 2026-12-31 14:05이다
- **WHEN** 사용자가 "산책을 했다"를 입력하고 저장 버튼을 누른다
- **THEN** 날짜 `2026-12-31`, 시간 `14:05`, 내용 "산책을 했다"인 기록이 저장된다
- **AND** 입력칸이 비워진다

#### Scenario: Enter 키로 저장
- **WHEN** 사용자가 입력칸에 내용을 입력하고 Enter 키를 누른다
- **THEN** 저장 버튼을 누른 것과 같이 기록이 저장된다

#### Scenario: 같은 날 여러 번 작성
- **GIVEN** 오늘 날짜로 이미 기록 1개가 저장되어 있다
- **WHEN** 사용자가 새 내용을 입력하고 저장한다
- **THEN** 기존 기록은 그대로 남고 새 기록이 별도로 추가된다

#### Scenario: 앞뒤 공백 제거
- **WHEN** 사용자가 "  커피 마심  "을 입력하고 저장한다
- **THEN** 내용이 "커피 마심"으로 저장된다

### Requirement: 빈 입력 거부
시스템은 비어 있거나 공백만 있는 입력을 저장하지 않아야 MUST 하며, 저장을 시도하면 내용을 입력하라는 경고 메시지를 입력칸 근처에 표시 SHALL 한다. 경고는 사용자가 다시 입력을 시작하거나 저장에 성공하면 사라진다.

#### Scenario: 빈칸 저장 시도
- **GIVEN** 입력칸이 비어 있다
- **WHEN** 사용자가 저장 버튼을 누르거나 Enter 키를 누른다
- **THEN** 기록이 저장되지 않고 목록이 바뀌지 않는다
- **AND** "내용을 입력해 주세요." 경고 메시지가 입력칸 근처에 표시된다
- **AND** 입력칸에 포커스가 간다

#### Scenario: 공백만 입력
- **WHEN** 사용자가 공백만 입력하고 저장 버튼을 누른다
- **THEN** 빈칸 저장 시도와 같이 저장되지 않고 경고 메시지가 표시된다

#### Scenario: 다시 입력하면 경고가 사라짐
- **GIVEN** 빈칸 저장 시도로 경고 메시지가 표시되어 있다
- **WHEN** 사용자가 입력칸에 글자를 입력한다
- **THEN** 경고 메시지가 사라진다

### Requirement: 입력 길이 제한
시스템은 한 줄 입력을 최대 100자로 제한 SHALL 한다.

#### Scenario: 100자를 넘게 입력
- **WHEN** 사용자가 100자를 넘게 입력하려고 한다
- **THEN** 입력칸에는 100자까지만 입력된다

### Requirement: 기록 유지
시스템은 저장된 기록을 같은 브라우저에서 새로고침하거나 다시 열어도 유지 SHALL 한다.

#### Scenario: 새로고침 후에도 남아 있음
- **GIVEN** 기록 3개를 저장했다
- **WHEN** 사용자가 페이지를 새로고침한다
- **THEN** 목록에 같은 기록 3개가 그대로 보인다

#### Scenario: 저장된 데이터가 손상됨
- **GIVEN** 브라우저에 저장된 기록 데이터가 읽을 수 없는 형식이다
- **WHEN** 사용자가 다이어리 화면을 연다
- **THEN** 화면은 오류 없이 빈 목록으로 열리고 새 기록을 저장할 수 있다

### Requirement: 기록 목록 표시
시스템은 저장된 모든 기록을 최신순으로 각 기록의 날짜, 시간, 내용과 함께 표시 SHALL 한다. 새 기록을 저장하면 목록에 즉시 반영된다.

#### Scenario: 최신순 정렬
- **GIVEN** `2026-12-30 22:40`, `2026-12-31 09:12`, `2026-12-31 14:05` 기록이 있다
- **WHEN** 사용자가 목록을 본다
- **THEN** `2026-12-31 14:05`, `2026-12-31 09:12`, `2026-12-30 22:40` 순서로 표시된다

#### Scenario: 같은 분에 저장한 기록
- **GIVEN** 같은 날짜·같은 분에 기록 A를 저장한 뒤 기록 B를 저장했다
- **WHEN** 사용자가 목록을 본다
- **THEN** 나중에 저장한 B가 A보다 위에 표시된다

#### Scenario: 저장 즉시 반영
- **WHEN** 사용자가 새 기록을 저장한다
- **THEN** 새로고침 없이 목록 맨 위에 그 기록이 나타난다

#### Scenario: 기록이 없을 때
- **GIVEN** 저장된 기록이 하나도 없다
- **WHEN** 사용자가 다이어리 화면을 연다
- **THEN** 목록 자리에 기록이 없다는 안내 문구가 표시된다

### Requirement: 목록 스크롤
시스템은 목록 영역을 기록 5개 높이까지만 보여주고, 기록이 5개를 넘으면 목록 영역 안에서 스크롤로 나머지를 볼 수 있게 SHALL 한다.

#### Scenario: 5개 이하
- **GIVEN** 기록이 5개 이하다
- **WHEN** 사용자가 목록을 본다
- **THEN** 모든 기록이 스크롤 없이 보인다

#### Scenario: 5개 초과
- **GIVEN** 기록이 8개다
- **WHEN** 사용자가 목록을 본다
- **THEN** 최신 5개가 보이고, 목록 영역을 스크롤하면 나머지 3개를 볼 수 있다
- **AND** 페이지 전체가 아니라 목록 영역만 스크롤된다

### Requirement: 기록 수정 시작
시스템은 목록의 모든 기록(지난 날짜 포함)에 수정 버튼을 표시 SHALL 하며, 사용자가 이를 누르면 그 항목을 목록 안에서 현재 내용이 채워진 입력칸과 저장·취소 버튼으로 바꿔야 MUST 한다. 편집 중인 항목은 한 번에 하나뿐이다.

#### Scenario: 수정 버튼으로 편집 시작
- **GIVEN** "산책을 했다" 기록이 목록에 있다
- **WHEN** 사용자가 그 기록의 수정 버튼을 누른다
- **THEN** 그 항목 자리에 "산책을 했다"가 채워진 입력칸과 저장·취소 버튼이 나타난다
- **AND** 입력칸에 포커스가 간다

#### Scenario: 지난 기록도 수정 가능
- **GIVEN** 어제 날짜의 기록이 있다
- **WHEN** 사용자가 목록을 본다
- **THEN** 그 기록에도 수정 버튼이 표시된다

#### Scenario: 다른 기록 편집으로 전환
- **GIVEN** 기록 A를 편집 중이며 입력칸 내용을 바꿨지만 저장하지 않았다
- **WHEN** 사용자가 기록 B의 수정 버튼을 누른다
- **THEN** A는 저장되지 않고 원래 내용으로 돌아간다
- **AND** B가 편집 상태가 된다

### Requirement: 수정 저장
시스템은 편집 중 저장 버튼 또는 Enter 키로 해당 기록의 내용을 앞뒤 공백을 제거한 새 내용으로 바꿔 저장 SHALL 하며, 처음 작성한 날짜·시간과 목록 순서는 바꾸지 않아야 MUST 한다. 저장 후 편집 상태가 끝나고 바뀐 내용이 목록에 보인다.

#### Scenario: 내용 수정 저장
- **GIVEN** `2026-11-12 22:40`에 쓴 "책 20쪽" 기록이 있다
- **WHEN** 사용자가 편집 입력칸을 "책 30쪽"으로 바꾸고 저장 버튼을 누른다
- **THEN** 그 기록의 내용이 "책 30쪽"으로 바뀌고 날짜·시간은 `2026-11-12 22:40` 그대로다
- **AND** 목록에서의 위치가 바뀌지 않는다

#### Scenario: Enter로 수정 저장
- **WHEN** 사용자가 편집 입력칸에서 Enter 키를 누른다
- **THEN** 저장 버튼을 누른 것과 같이 수정이 저장된다

#### Scenario: 새로고침 후에도 수정 유지
- **GIVEN** 기록을 수정해 저장했다
- **WHEN** 사용자가 페이지를 새로고침한다
- **THEN** 수정한 내용이 그대로 보인다

#### Scenario: 상단 입력과 독립
- **GIVEN** 상단 새 기록 입력칸에 내용을 적어 둔 상태에서 다른 기록을 편집 중이다
- **WHEN** 사용자가 편집을 저장한다
- **THEN** 상단 입력칸의 내용은 그대로 남고 새 기록은 추가되지 않는다

### Requirement: 수정됨 표시
시스템은 내용이 실제로 바뀐 기록에 "수정됨" 표시를 보여줘야 SHALL 하며, 내용이 같으면 수정으로 보지 않아야 MUST 한다.

#### Scenario: 수정한 기록에 표시
- **WHEN** 사용자가 기록 내용을 다른 내용으로 수정해 저장한다
- **THEN** 그 기록에 "수정됨" 표시가 나타나고 새로고침 후에도 유지된다

#### Scenario: 내용이 같으면 표시하지 않음
- **GIVEN** 한 번도 수정하지 않은 "아침 커피" 기록이 있다
- **WHEN** 사용자가 편집을 열고 내용을 바꾸지 않은 채(또는 앞뒤 공백만 더해) 저장한다
- **THEN** 편집 상태가 끝나고 "수정됨" 표시는 나타나지 않는다

### Requirement: 수정 취소
시스템은 편집 중 취소 버튼 또는 Esc 키로 변경 내용을 버리고 원래 내용으로 되돌려야 SHALL 한다.

#### Scenario: 취소 버튼
- **GIVEN** 기록을 편집하며 입력칸 내용을 바꿨다
- **WHEN** 사용자가 취소 버튼을 누른다
- **THEN** 편집 상태가 끝나고 기록은 원래 내용 그대로다

#### Scenario: Esc 키
- **WHEN** 사용자가 편집 입력칸에서 Esc 키를 누른다
- **THEN** 취소 버튼을 누른 것과 같이 원래 내용으로 돌아간다

### Requirement: 수정 입력 검증
시스템은 편집 입력에도 새 기록 작성과 같은 규칙을 적용 SHALL 한다: 최대 100자, 비어 있거나 공백만 있으면 저장하지 않고 경고 표시, 한글 조합 중 Enter로는 저장하지 않음.

#### Scenario: 빈칸으로 수정 저장 시도
- **GIVEN** 기록을 편집하며 입력칸을 모두 지웠다
- **WHEN** 사용자가 저장 버튼을 누른다
- **THEN** 기록은 원래 내용 그대로이고 편집 상태가 유지된다
- **AND** "내용을 입력해 주세요." 경고가 편집 중인 항목 근처에 표시되고, 다시 입력하면 사라진다

#### Scenario: 100자 제한
- **WHEN** 사용자가 편집 입력칸에 100자를 넘게 입력하려고 한다
- **THEN** 100자까지만 입력된다

#### Scenario: 한글 조합 중 Enter
- **WHEN** 사용자가 편집 입력칸에서 한글을 조합하는 중에 Enter 키를 누른다
- **THEN** 조합만 확정되고 수정은 저장되지 않는다

### Requirement: 편집 중 목록 높이 유지
시스템은 편집 상태에서도 항목 높이를 다른 항목과 같게 유지해, 목록이 5개 높이까지 보이고 넘치면 목록 영역 안에서 스크롤되는 동작이 바뀌지 않게 SHALL 한다.

#### Scenario: 편집 중 스크롤 유지
- **GIVEN** 기록이 8개이고 그중 하나를 편집 중이다
- **WHEN** 사용자가 목록을 본다
- **THEN** 목록 영역에는 여전히 5개 높이만 보이고 목록 영역 안에서 스크롤된다
